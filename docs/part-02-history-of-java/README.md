# Part 2 — History of Java

Java did not fall from the sky as a job requirement. People built it to solve a real problem: **write a program once, run it on many kinds of machines**.

This part is a story, not a trivia contest. You do **not** need to memorize every release. You need a mental timeline so later words (bytecode, JVM, LTS, OpenJDK) have a home.

---

## What This Part Is For

By the end of Part 2 you should be able to say:

> Java started as Oak at Sun Microsystems, led by James Gosling, and became public around 1995. "Java" can mean the language, the specification, the trademark, or a JDK you install. The language grew in a few big waves (especially 5, 8, and the modern LTS line). I will learn features when I need them, not recite every version number.

## How to Study Part 2

- Read for **plot**, not for flashcards.
- When you see a feature name (generics, lambdas, records), treat it as a street name on a map. You will walk those streets later.
- Do not pause the course to memorize Java 9, 10, 12, 13, 14, 15, 16, 18, 19, 20, 22, 23, 24 as a list. That is not how professionals work.

---

## SDET Thread

Automation jobs say "Java" in the posting. Interviewers mean:

- Can you write Java that a team can read?
- Do you know what JDK you are on?
- Do you understand that Selenium / Rest Assured / JUnit run **on** Java, they are not a replacement for Java?

History gives you the vocabulary to answer "Why Java for testing?" without shrugging.
