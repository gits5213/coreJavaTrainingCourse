# Part 39 — SOLID Principles

Teach SOLID **after** you are fluent in classes, interfaces, and composition. These letters are not magic. They are names for design pains you should already be feeling.

```text
S   Single Responsibility
O   Open/Closed
L   Liskov Substitution
I   Interface Segregation
D   Dependency Inversion
```

Each principle below uses practical Java. The SDET example is mandatory: a `LoginPage` that also does database, API, data, screenshots, email, and logging is a design failure.

## Prerequisite

OOP proficiency: class, interface, composition. If `LoginPage` still looks like a bag of static methods, go back to Part 12.
