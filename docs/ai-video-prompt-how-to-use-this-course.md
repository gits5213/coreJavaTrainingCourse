# AI Video Prompt — How to Use This Course (for non-technical people)

Use this file with tools such as HeyGen, Synthesia, InVideo, Google Veo, Runway, Pika, or a talking-head + B-roll editor.

**Goal of the video:** a complete beginner who is a little afraid of computers should finish watching and know *exactly* what to open, what to ignore for now, and how to study Chapter 1 without feeling lost.

**Audience:** people who have never programmed, never used IntelliJ, and may not know what Java, Git, Maven, or “SDET” means.

**Tone:** calm, warm, patient teacher. Never sarcastic. Never “it’s easy.” Honest: you will be confused sometimes, and that is normal.

**Length options:**
- **60 seconds** — teaser / social
- **3 minutes** — orientation
- **7–8 minutes** — full “how to use this course” (recommended)

---

## 1. Master prompt (paste this first)

```text
Create a friendly educational explainer video for complete beginners with zero technical knowledge.

VIDEO TITLE:
How to Use This Java SDET Course (Even If You Don't Know What Java Is)

COURSE NAME:
Java Programming & Software Engineering for SDET

WHO IT'S FOR:
Someone who may know nothing about computers, programming, Java, testing, Git, or IDEs. They might be a career changer, a manual tester, a parent returning to work, or a student who feels “not a tech person.”

WHAT THE VIDEO MUST DO:
1. Welcome them. Tell them they are in the right place.
2. Translate scary words into plain English (Java, SDET, JDK, IntelliJ).
3. Show the destination in one sentence: they will learn to write, test, debug, and later design professional Java programs and test automation.
4. Show they start at ZERO: “What is a computer?” not “install Selenium.”
5. Walk through the folder like a house tour: README, docs, lessons, projects, assessments, capstone.
6. Tell them the first three clicks: README → How to Use This Course → Chapter 1.
7. Explain how each chapter works (15-step class). Stress: read the goal, type the code, expect to fail, then debug.
8. Tell them what NOT to do: do not skip to Selenium, do not copy-paste without typing, do not open the capstone on day 1, do not memorize syntax like a dictionary.
9. Tell them what they need: a computer, curiosity, patience. Software (Java JDK and IntelliJ) comes in Part 4. They can read Chapters 1–3 with no install.
10. End with one clear next action and encouragement.

STYLE:
- Clean modern explainer, light background, soft teal and navy (professional, not neon startup)
- Friendly instructor on camera OR a calm narrator over simple motion graphics
- Large on-screen text. Short phrases. High contrast.
- Simple icons: computer, recipe card, toolbox, staircase, folder, lightbulb
- Screen mockups of a folder tree, not real dense code until a tiny Hello World at the end
- No stock “hacker in a hoodie,” no Matrix rain, no flashing terminal porn
- Inclusive: show a mix of ages; a person at a kitchen table laptop is better than a Silicon Valley office

VOICE:
- Warm adult instructor, clear American or neutral English, moderate pace
- Pause after new words
- Smile in the voice
- Reading level: grade 6–8. One idea per sentence.

ON-SCREEN TEXT RULES:
- Max 6–8 words per title card
- Spell out acronyms the first time
- Never show a wall of code
- When showing Hello World, show 8–12 lines max, large font

MUSIC:
Soft hopeful piano or light acoustic. Low volume under voice. No drop-bass.

DO NOT:
- Promise “learn Java in 24 hours”
- Shame people for being beginners
- Use unexplained jargon
- Make the capstone look like homework for day one
```

## 2. Full voiceover script (7–8 minutes)

Read this exactly, or use it as the spoken track.

---

**[0:00–0:25 | Welcome]**

If you have never written a computer program… if the word Java sounds like coffee… if someone said “SDET” and you nodded but did not know what it meant… this video is for you.

You do not need a computer science degree. You do not need to be “good at math.” You do not need to already know how to code.

You need a computer, some curiosity, and a willingness to go slowly.

This course was built for people who start at zero.

**[0:25–0:55 | What this course is]**

The full name is: Java Programming and Software Engineering for SDET.

Let me translate that.

Java is a language we use to give instructions to a computer. Like a very precise recipe.

SDET means Software Development Engineer in Test. In plain English: a person who writes programs that check other programs. If a login button is broken, or a payment fails, an SDET helps catch that with code.

That sounds advanced. We will not start there.

We start with a simple question: what is a computer?

**[0:55–1:25 | The journey, not the mountain]**

By the end of the whole program, you should be able to say:

“I can design, write, test, debug, and care for professional Java software and test automation.”

That is the last chapter of a long book. Not tonight.

Think of a staircase, not a leap.

First you learn what a computer is.
Then what programming means.
Then where Java came from.
Then how to install tools.
Then your first tiny program that prints: Hello, Java.

Only much later: testing, websites, APIs, and big frameworks.

If you skip to the fancy stuff, you will feel stupid. You are not stupid. You skipped the stairs.

**[1:25–2:10 | Open the folder — house tour]**

When you open this course on your computer, you will see folders. Do not panic. A folder is just a labeled box.

Here is the house tour.

The file called README is the front door. Read that first.

The folder called docs is the classroom. The lessons live there, chapter by chapter.

The folder called lessons is a practice kitchen. It has small Java programs you can run when the chapter says so.

The folder called projects is where you build real mini-programs. Project one is literally “Hello Java.” Not a robot army.

The folder called assessments is quizzes, exams, and interview practice. Use those after you study, not before.

The folder called capstone is the graduation building. Do not move in on day one. Architecture comes last, on purpose.

**[2:10–2:40 | Your first three clicks]**

Here is exactly what to do today. Three steps.

One. Open README. Skim it. You do not have to understand every word.

Two. Open the file “How to Use This Course” inside the docs folder. That is your student handbook.

Three. Open Chapter 1: What is a computer?

Do not install anything yet if that stresses you. Chapters 1, 2, and 3 are reading. Tools come in Part 4.

**[2:40–3:40 | How a chapter works]**

Every chapter is a class, not a blog.

It always follows the same order, so your brain can relax.

First: today’s goal. One sentence. If you cannot say the goal out loud, do not start typing.

Second: why it matters. Why should a tester or a beginner care?

Third: a real-life analogy. We use restaurants, banks, labeled boxes. Analogies are bridges. Then we walk across to the computer idea.

Then a simple picture or diagram. Trace it with your finger.

Then the smallest example.

Then a work example: a user, an order, a login.

Then an SDET example: how a quality engineer uses the same idea.

Then we break the code on purpose. Yes, on purpose. We want you to see a mistake in a safe room.

Then we debug. Debugging means: find what went wrong, fix one thing, try again.

Then you try. Then a harder challenge. Then a short quiz. Then one interview question out loud. Then homework.

A chapter often takes 45 to 90 minutes. If it takes three hours because you are thinking, that is learning, not failure.

**[3:40–4:20 | The most important rule]**

Do not memorize Java like a phone book.

Professionals follow a path:

Name the problem.
Understand it.
Write the steps in ordinary English. That is called an algorithm. It just means a clear list of steps.
Then pick the Java idea that matches.
Then type the code.
Then run it.
Then it will fail sometimes.
Then you debug.
Then you clean it up.
Then you test it.
Then, much later, you design bigger systems.

The short version, write this on a sticky note:

Do not start typing until you can explain the steps out loud.

**[4:20–5:00 | How to study without burning out]**

Type the examples with your own fingers. Do not only copy-paste. Typing trains your eyes.

When you see red errors, breathe. Read the first error. Fix one thing. Run again.

Use the Answer Key at the end of a chapter after you try, not before.

Practice the interview question out loud, even if you feel silly. Jobs are spoken, not only typed.

Homework is not optional if you want the skill. Skipping homework is how people “watch” a course and still cannot code.

You do not have to be fast. You have to be honest.

**[5:00–5:35 | What you will install — later]**

In Part 4 you will install two tools.

First, the JDK. That is the Java toolkit. Think of it as the stove and the pans. This course recommends a long-term version called JDK 25 LTS. LTS just means “supported for a long time.” If that number changes at work later, the ideas still count.

Second, IntelliJ IDEA. That is a smart notebook for Java. Community edition is enough. It is not the language. It is the desk you sit at.

You will also meet Git later. Git is how we save history of our work so we stop making files named final-final-really-final.

None of that is Chapter 1.

**[5:35–6:10 | What not to do]**

Please do not:

Skip Chapter 1 because it feels “too basic.”
Jump to Selenium or the capstone to impress someone.
Memorize every Java version number.
Hide from errors.
Compare your day three to someone else’s year three.

This course is a path from:

“I don’t know what Java is”

to:

“I can write it, test it, and explain it.”

That path is long because the job is real.

**[6:10–6:45 | Levels, in human language]**

You start as a computer beginner. Hardware and software. Input and output.

Then you become a Java explorer: variables, if, loops.

Then a programmer: methods, classes.

Then a developer: objects, lists, files, mistakes that get handled on purpose.

Then an automation engineer: tests that run themselves.

Then an SDET: websites, APIs, databases, teamwork with Git.

Then, if you keep going, a senior person who reviews code and designs systems.

You are allowed to be Level 0. Every architect in this field was Level 0 once.

**[6:45–7:20 | Close + next action]**

Here is your next action. Pause the video and do it now.

Open the course folder.
Open README.
Open How to Use This Course.
Open Chapter 1.

Read today’s goal. Say it in one sentence.

Then go make a cup of something. You just started a professional path, not a weekend trick.

Welcome. We will go slowly. We will go in order. And you do not have to know Java yet.

You only have to begin.
